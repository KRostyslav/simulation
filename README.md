
# simulation

Монорепа навчальних симуляцій з фізики. Кожна гра пояснює тему через наслідки
дій гравця, а не через текстовий урок.

## Що всередині

| Пакет | Призначення |
| --- | --- |
| [apps/semiconductor](apps/semiconductor) | Піксельна лабораторія напівпровідників: власна і домішкова провідність, p-n перехід |
| [packages/pixel-ui](packages/pixel-ui) | Піксельний UI-шар: canvas із цілочисельним масштабом, палітра, примітиви малювання, віджети |
| [packages/explain](packages/explain) | Ядро пояснень: величина не існує окремо від формули й причини |

## Запуск

```bash
pnpm install
pnpm dev --filter @edu/semiconductor   # одна гра
pnpm dev                               # усі застосунки
pnpm build                             # збірка
pnpm test                              # тести
pnpm lint                              # перевірка синтаксису
```

Потрібен Node ≥ 20 і pnpm. Turborepo кешує результати тасків — повторна збірка
без змін завершується миттєво.

Тести фізики й `@edu/explain` не мають зовнішніх залежностей, тому
запускаються навіть до `pnpm install`:

```bash
cd apps/semiconductor && node --test
cd packages/explain   && node --test
cd packages/pixel-ui  && node --test
```

## Принцип, спільний для всіх симуляцій

Показник — це не число, а `Readout`: значення разом із причиною, чому воно
таке, і формулою, з якої воно отримане.

```js
makeReadout({
  id: "sigma",
  label: "Питома провідність",
  value: 2.0,
  why: "Добуток кількості носіїв на їхню рухливість…",
  formula: "σ = q·(n·μₙ + p·μₚ)",
  substitution: "σ = 1,60·10⁻¹⁹ · ({n}·{muN} + {p}·{muP}) = {sigma} См/см",
  terms: { n: "1,00·10¹⁶", muN: "1248", p: "6,40·10³", muP: "437", sigma: "2,00" },
});
```

Створити показник без `why` технічно неможливо — `makeReadout` кине помилку.
Так само неможливо лишити в підстановці плейсхолдер без значення.

Навіщо так строго: найгірша помилка в навчальному застосунку — коли розрахунок
змінили, а підпис під ним лишився старим. Учень довіряє підпису й вивчає
неправду. Тут панель, живий коментар і довідник рендерять той самий об'єкт,
який повернула фізика, тому розійтися з нею вони не можуть за побудовою.

## Як додати нову симуляцію

1. Створіть `apps/<назва>` з `package.json` (`"name": "@edu/<назва>"`),
   `index.html` і `vite.config.js` — за зразком `apps/semiconductor`.
2. Додайте залежності `"@edu/pixel-ui": "workspace:*"` і `"@edu/explain": "workspace:*"`.
3. Опишіть предметну модель окремо від UI, під тестами, і лише потім малюйте.
4. Реєструвати щось у `turbo.json` не потрібно — таски `dev`, `build`, `lint`,
   `test` уже описані в корені й підхопляться автоматично.

Спільне виносьте в `packages/`, а не в сусідній застосунок: пакети — це те,
чим ігри обмінюються, і залежність між двома `apps/*` є помилкою архітектури.
